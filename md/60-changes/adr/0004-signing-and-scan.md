# ADR-0004：强制授权签名与恶意代码检测

- 状态：Proposed
- 日期：2026-10-28
- 后续补充：[ADR-0005](0005-termux-repo-signature.md) 增加仓库签名（Termux/OpenPGP）路径，包签名仍优先。
- 关联设计：[lb 设计文档](../../00-design/lb-architecture.md)
- 格式规范：[LBPA v1](../../00-design/lbpa-format.md)
- 补充：[ADR-0002](0002-lb-system-exposure.md)、[ADR-0003](0003-lbpa-format.md)

## 背景

- 防止安装恶意“格机包”（清数据、刷分区、改系统、装后门）。
- 默认只允许由用户根证书签发的授权包；信任模型类似 HTTPS 证书链。
- 即使签名通过，也要对包做基础静态恶意检测；命中明显恶意代码时阻止并删除包。
- 开发者模式需分别关闭“强制签名”和“自动检测”两个策略。

## 决策

1. **证书链**：用户根证书（自签）→ 二级证书（可签包或再签发叶证书）→ 包签名；算法 ECDSA P-256 + SHA-256，JSON 证书，语义对齐 X.509。
2. **默认强制签名**：`require_signature=true`；无签名、链断、过期、用途/包名前缀不符、撤销、签名/哈希错误均拒绝。策略关闭时允许未签名，但“有签名却验证失败”仍拒绝。
3. **签名位置**：LBPA 用尾部 footer（证书链 + 签名），签名覆盖 manifest 原始字节哈希 + payload 哈希；deb 用同名 `.sig` 分离签名，覆盖整个文件。
4. **信任根**：用户根证书公钥固定在 `/data/local/lb/trust/root.json`；根私钥建议离线，设备生成时强警告并 600 权限；撤销列表由根签名。
5. **静态恶意检测**：检查脚本、钩子、ELF 字符串与结构；明确恶意规则（`rm -rf /`、`dd of=/dev/block`、`mkfs`、`reboot recovery`、`setenforce 0`、写 `/system`、篡改 root 管理器目录等）阻断安装，并删除 lb 缓存包；本地导入文件默认隔离并确认删除。
6. **开发者模式**：两个独立开关（强制签名、自动检测），默认开启；关闭检测仍做结构校验；关闭签名不豁免坏签名。
7. **包格式**：签名只接受证书链到用户根；不信任自签名包、不复用 deb 的仓库信任。

## 后果

- 未签名的 Termux 官方 deb 在本 ADR 下默认无法安装；[ADR-0005](0005-termux-repo-signature.md) 补充仓库签名路径后，Termux 官方默认可以安装。
- 首次使用必须先建立信任根（`lb ca init` 或 `lb trust import`），否则所有安装被拒。
- 需要实现证书签发、签名、验证、撤销与信任库管理工具（`lb ca/sign/verify/trust`）。
- 静态检测存在误报/漏报；需展示命中规则并提供开发者开关。
- 根私钥在设备上生成会降低安全边界；文档需强调离线保管。
- 本地文件删除有数据丢失风险，采用“隔离 + 确认删除”，缓存副本自动删除。

## 备选方案（未采用）

| 方案 | 原因 |
|---|---|
| 只校验 SHA-256 | 无法证明来源，索引/下载可被替换 |
| 使用 deb 仓库签名（Release/InRelease） | 只保护索引，不约束单个包的构建者；与 lb 信任根无关 |
| 自签名包信任（TOFU） | 无法满足“只有我签发的证书可装” |
| 强制所有包签名且无开发者开关 | 用户明确要求开发者模式可分别关闭 |
| 直接把恶意包原文件删除 | 容易误删用户数据；改为缓存删除 + 本地隔离确认 |
